# Reconciliation report

Generated by `uv run python -m scripts.recon_eval` on Darwin arm64, Python 3.12.13.

## Method

`services/recon/generator.py` builds a consistent business day (ledger nostro postings, switch log, bank statement), then plants labelled breaks on the bank side: missing at bank, missing internally, amount mismatch, duplicate, status mismatch, timing difference (moved to the next day's statement), bank fee/GST deduction and an unattributable line. Each case writes the statement in the bank's format and parses it back before reconciling. **Hard** mode (bank C style) also removes the merchant reference from 5% of UPI lines *before* planting, so breaks also land on lines that can only be matched fuzzily. Cases with and without the next day's statement are both measured.

Recall = planted breaks detected / planted. Precision = reported breaks that correspond to a planted break / reported. Classification accuracy = detected breaks with the right type / detected.

The engine is pure Python with hash-indexed matching (linear in lines). Database persistence of matches and breaks is measured separately in the load-test report.

## Iteration history

- First hard-mode run (10 seeds x 20,000): recall 100%, but 40 of 4,320 planted breaks were misclassified and 24 false breaks were reported. Amount mismatches on lines without a reference produced an `unknown` bank line plus `missing_at_bank`; timing differences on such lines were reported as `missing_at_bank`.
- Fix: a second fuzzy stage pairs a reference-less line to a unique record with the same payer VPA and time window when amounts differ, and next-day carry-over also matches reference-less lines by kind, amount and VPA.
- Integration run on real services found that the fixed-width writer silently truncated 41-character simulator references to 24 characters, hiding duplicates. The writer now refuses to truncate and the simulator emits 16-character UTRs.

## Limits

- The generator and engine were written by the same team; the hard mode and the real-service integration test (`tests/integration/test_reconciliation.py`) exist to reduce that bias, but results on real bank files would be lower.
- Scope is the platform nostro: UPI transfers, refunds and payouts. Card acquirer settlements and chargebacks are not reconciled.
- Exact ties in fuzzy matching (same amount, VPA and time distance) are reported as `unknown` rather than guessed.
